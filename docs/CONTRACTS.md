# Contracts

Three Rust contracts built with `near-sdk` 5 in `contracts/`.

| Contract | Role |
|---|---|
| `circle` (`cowrie-circle`) | Holds many circles keyed by id. Holds NEP-141 tokens, collateral, safety pot and contributions. Enforces schedule, settlement and defaults. No admin withdrawal. |
| `credential` (`cowrie-credential`) | Soulbound credential. NEP-171-style views, `nft_transfer` always panics. Only the registered circle contract can mint. Also exposes `credential_count`, `credentials_of` and `score`. |
| `mock-usdc` | NEP-141 test token, 6 decimals, capped public faucet (10,000 per account). Test only. |

## Design decisions

- **One contract, many circles** (the fallback named in the build spec) rather than a sub-account deployed per circle. It avoids per-circle deployment cost and keeps the state in one place. The factory/sub-account design remains a roadmap item.
- **Rules live in `contracts/circle/src/engine.rs`**, a line-for-line port of `src/engine/circle.ts` with no NEAR runtime calls, so they can be tested natively and replayed against the TypeScript engine.
- **Deposits** use `ft_transfer_call` with a JSON message: `{"action":"join","circle":1}`, `{"action":"contribute","circle":1,"round":0}`, `{"action":"prepay","circle":1}`. Wrong amounts or rounds panic, which refunds the transfer.
- **Credential discount** on join is checked by a cross-contract view (`credential_count`) and a callback. If the amount sent does not match the required collateral, the whole amount is refunded.
- **Auto-start**: the circle starts in the transaction that fills the last seat.
- **Events**: NEP-297 style logs (`EVENT_JSON:{"standard":"cowrie",...}`) for created, joined, started, contributed, prepaid, autopaid, defaulted, slashed, reserve_used, tip, settled, finished, credential_minted, seat_transferred, left, cancelled.

## Known v1 limits

- At most **12 members** per circle on-chain. The engine supports 24; the cap keeps `finish` (transfers plus one credential mint per member) inside one transaction's gas.
- Outgoing payouts are fire-and-forget `ft_transfer` calls. The mock token auto-registers receivers, so they do not fail; a real token that requires storage registration could fail a payout, and v1 does not retry.
- Random order uses a seed derived from `env::random_seed()` and can be influenced by block producers.
- Seat transfer is initiated by the creator (the creator is the approver), not by the outgoing member.
- Unaudited.

## Tests

```bash
cd contracts && cargo test --release
```

- `circle/tests/vectors.rs` replays 300 scenarios generated by the TypeScript engine (`npm run vectors`) and requires identical payouts, recipients, balances, ledgers and removals, plus conservation after every settle and idempotent finish.
- `credential` unit tests: only the minter mints, transfers always fail, score formula.
- `mock-usdc` unit tests: faucet and cap.
